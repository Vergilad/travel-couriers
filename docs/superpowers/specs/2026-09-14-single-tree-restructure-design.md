# Design: single-tree restructure + dead-code sweep (2026-09-14)

Goal: one normal repo checkout (`backend/`, `frontend/`, `db/`, `docs/`,
`compose.yml`). Today there are two half-checkouts: main holds the new
backend plus the retired Supabase-era `frontend/`; the `.delta` checkout
holds the same commit but its `frontend/` is the real Viactor app. Both
trees are ~90 files dirty, nothing committed since `afee6e3`.

Decisions (all approved): approach A directory swap; checkpoint commits
first (one per tree, per-scope splitting waived as infeasible);
deletion scope = dead frontend files, empty `infra/` + committed junk,
unused backend deps, Supabase `.env` keys, `review.md` archived.

## 1. Checkpoint commits

- Main: `git add -A`, commit `checkpoint: self-hosted backend, handover
  code, ship hardening (uncommitted session work)`. Staged deletions of
  `supabase/`, `sql/` ride along by intent.
- `.delta` checkout (`jxtftjq7g77d`, own clone): same, message
  `checkpoint: viactor frontend through ship fixes`.
- Gate: both trees `git status` clean before any destructive step. Any
  commit failure stops the work.

## 2. The swap (main repo only)

1. `git rm -r frontend` (retired tree goes; its untracked
   `frontend/.env` with Supabase keys is deleted from disk in step 1b —
   the file was never tracked).
1b. Delete untracked remainders from disk: `frontend/.env`,
   `frontend/node_modules/` (retired tree's install), `frontend/dist/`.
2. Copy `.delta/.../frontend/` to `frontend/`, excluding `node_modules/`,
   `dist/`, `tsconfig.tsbuildinfo` (regenerated by builds).
3. `git add frontend`; commit `single tree: viactor frontend becomes the
   repo frontend`.
4. Delete main `frontend/node_modules/` only if it survived step 1b,
   fresh `npm install`, `npm run build` green before proceeding.
5. Dev moves to main `frontend/` (:5000). Kill the worktree dev server last.

## 3. Dead-code sweep (import-grep verified)

Delete: `frontend/src/components/ui/{button,badge,input,listing-row}.tsx`,
`frontend/src/hooks/use-pointer-position.ts`, empty `infra/`, tracked
`frontend/tsconfig.tsbuildinfo` (`git rm`), untracked `frontend/dist/`
(disk). Trim
`fetchOpenListings` from `frontend/src/lib/api.ts` (keep `authedFetch`
re-export). Deps: drop `resend`, `httpx` (backend); drop `shadcn`,
`@base-ui/react`, `class-variance-authority`, `clsx`, `tailwind-merge`
(frontend) + fresh install. Move root `review.md` to
`docs/review-supabase-era.md` and repoint its two live references in
`SYSTEM_PROMPT.md` (§1 ask_user example, §3 override rule). Commit
`sweep dead code and unused deps`.

Kept deliberately: `framer-motion` (Nav, Footer, CityAutocomplete),
`useLanguage`, `ui/sheet-grid`, old-chrome `layout/Nav+Footer`,
`tw-animate-css`, `SKILLS/`, `scripts/`.

## 4. Verification

Backend: image rebuild, `/health`, OpenAPI routes, rerun deal+code and
ship-fix probes against the live DB. Frontend: `npm run build`,
locale parity 559/559, dash scan, authenticated headless probe from the
new tree (needer code, carrier entry, modal, zero page errors). Final
`git status` + tree review.

## 5. Untouched

`.delta/` entirely (harness-owned; `wbm` keeps its untracked RLS drafts),
`frontend.zip` (106MB, unknown, outside repo), `CONTEXT/`, `docs/`, `db/`,
live `backend/.env`, `backend/data/`, `payments` table.

## Interfaces and rollback

No API, DB, or user-facing changes. Every step is a git commit:
rollback is `git reset --hard <checkpoint>` per tree. No data migrations.
